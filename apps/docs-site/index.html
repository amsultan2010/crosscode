Features

A coordination layer, not another Git wrapper

Turn it off and your repository is exactly what it was.

  • Live proposals. Remote edits arrive as reviewable diffs, never as writes into your files.
  • One-command accept. Crosscode re-checks your base, takes a checkpoint, then applies.
  • End-to-end encrypted. Contents, paths, and diffs are sealed on your machine first.
  • Path claims. Agents ask who owns a file before they start writing to it.
  • Live presence. See which people and agents are working in the repo right now.
  • MCP native. A standard stdio MCP server, so there is no editor extension to install.
  • Publish to Git. Accepted proposals become commits on a real branch, dry run first.
  • Survives the network. The daemon keeps capturing offline and catches up from its cursor.

Safety

Five rules it will not break

The whole product stops one step short of typing into your files, which is the one thing you never want in code.

Full detail on the safety model page.

  1. Your files are authoritative for your own work.
  2. Remote operations arrive as proposals, never applied automatically.
  3. Every write re-checks the local base and creates a checkpoint first.
  4. Excluded paths, apparent secrets, escaping symlinks, and mismatched hashes are refused.
  5. Payloads are encrypted before they leave your machine.

Encryption

We do not have the key to your code

Your edits pass through our service, so the code is encrypted on your machine first, under a workspace key we never receive. Here is exactly what is left in the clear.

Encrypted on your machine

  • File contents
  • File paths
  • Diffs
  • Content hashes
  • Change intents

A database dump or a subpoena gets ciphertext.

Visible to the service

  • Account email, workspace, device, and project identifiers
  • Your repository's Git remote URL
  • Timestamps, file counts, payload sizes
  • Whether a file changed, but not which file
  • Task titles, claim targets, and handoff notes, not yet encrypted

If any of that is confidential for you, self-host the service.

No third-party model provider is in the loop either. The AI reviewer runs on the coding agent already connected to your machine. Read the privacy page.

Install

One command, in the repo your team shares

It configures the checkout, signs you in, starts the daemon, and registers the MCP server with your agent. Re-running it is safe.

run in your project 
npx @crosscode/cli start

Using it daily? Install it properly so the daemon runs from a stable path: npm install -g @crosscode/cli, then crosscode start. To bring a teammate in, generate an invite and have them run crosscode join --invite <code>.

Or hand the whole setup to your coding agent

Paste this into Claude Code, Codex CLI, OpenCode, Cursor, or any MCP-capable agent. It runs the same command and wires up the MCP config itself.

paste into your coding agent 
Set up Crosscode for this project. Crosscode syncs uncommitted working-tree files between
my teammates' checkouts and mine in real time: they edit, my copy updates within seconds,
and vice versa. It never touches commits, branches, or remotes. Do the following:

1. Check that Node 24 or newer is available (`node --version`). If it is not, stop and
   tell me, because everything below needs it.
2. From this project's Git root, run:

   ```
   npm install -g @crosscode/cli && crosscode start
   ```

   `start` does the whole setup: it signs me in with GitHub, attaches this checkout to a
   project, starts the background daemon, and installs the Crosscode MCP server, skill,
   and pre-edit hook for you. It is safe to re-run.
3. It will print a GitHub sign-in URL. Show it to me and wait. I have to open it and sign
   in before the command finishes. Do not try to sign in for me and do not ask me for
   credentials.
4. Once `start` reports success, tell me I need to restart you (or reconnect MCP servers)
   for the "crosscode" server to be picked up.
5. Once reconnected, call the `status` tool once to confirm it works. If it fails, show me
   the exact error rather than guessing at a fix.

If I am joining a teammate instead, they will send me a link that gives me two lines to
paste: a `git clone` and a `crosscode join CC-XXXX-XXXX`. Run those from the parent
directory rather than the steps above.

After setup, read the `crosscode` skill and follow it. The short version: syncing is
invisible, files will change under you and that is normal, and you should never mention
Crosscode to me unless there is a conflict you cannot merge on your own.

Codex CLI's config is TOML and start does not write it, so Codex users add a three-line entry by hand. See MCP client setup.

Pre-1.0, and honest about it

  • Live push on the hosted service is polling, so remote work appears on the next sync. Self-hosting gets the WebSocket path.
  • No live payment account exists yet, so nothing is chargeable today. Plan limits are still enforced server-side.
  • Task titles, claim targets, and validation output are not encrypted yet. File payloads are.
  • There is no web app and there will not be one. Workspaces, invites, and billing are CLI and API only.

Questions

Asked before installing

Can you read my code?

No. Contents, paths, diffs, hashes, and change intents are encrypted on your machine with a key we never receive. The privacy page lists everything we can see.

What happens if I lose the encryption key?

You lose the coordination history, meaning past proposals and their diffs. You lose no source code, because your repository is an ordinary Git repository on your disk the whole time. Print a recovery code with crosscode key export, and any paired machine can hand the key to a new one.

Can it rewrite my branch history or force-push?

No. Crosscode never stages, commits, pushes, resets, rebases, or changes remotes on its own, and it never moves HEAD. Checkpoints live under refs/crosscode/checkpoints/, outside branch history.

Does my code get sent to an AI provider?

No. The reviewer for ambiguous conflicts runs on the coding agent already connected to your machine. That is also why AI review is unlimited on every plan including free: it costs us nothing.

What happens if I stop running it?

Nothing about your checkout changes. It was an ordinary Git repository the whole time, so there is no lock-in format to migrate away from.

Is it worth it for one person?

No. Crosscode is built for a shared codebase with more than one person on it. If a repository will only ever have you in it, plain Git is the better tool.
