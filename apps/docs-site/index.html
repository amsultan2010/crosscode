Coordination for teams whose agents all write at once

Everyone has their own copy of the code. Someone merges it all at the end.

That is how writing worked before Google Docs. Crosscode closes the same gap for code. A small daemon sits in each teammate's checkout, captures an edit once it has settled, and puts it in front of everyone else within seconds. It stops one step short of typing into your files, which is the one thing you never want in code. Remote work arrives as a proposal, and one command takes it.

How it works

One daemon per checkout, MCP on one side, a coordination service on the other

  1. A background program watches your checkout

    One small daemon per Git worktree. It watches your files and your Git activity, waits until an edit has settled, and records it without moving HEAD, staging anything, or touching your branch.

  2. Your agent talks to it over MCP

    The daemon is a standards-compliant MCP server. Claude Code, Codex CLI, OpenCode, Cursor, Gemini CLI, and VS Code all connect to it. There is no editor plugin to install.

  3. Work syncs through a shared service

    Recorded edits go to a coordination service backed by PostgreSQL, so every other checkout sees the same history. If it is unreachable, the daemon keeps capturing and catches up from its saved cursor.

  4. Remote work arrives as a proposal

    Nothing from another checkout is written to your files automatically. Before a proposal is applied, Crosscode re-checks that your files still match the base it was built on and takes a checkpoint it can roll back to.

The five rules it will not break

  1. Your files are authoritative for your own work.
  2. Remote operations arrive as proposals and are never applied automatically.
  3. Every write re-checks the local base and creates a checkpoint first.
  4. Excluded paths, files that look like secrets, symlinks leaving the repository, and payloads whose content does not match its hash are refused.
  5. File payloads are encrypted before they leave your machine, so the service stores code it cannot read.

Checkpoints live under refs/crosscode/checkpoints/ and never appear in branch history. Full detail on the safety model page.

Encryption

We do not have the key to your code

Your edits pass through our coordination service, so the code itself is encrypted on your machine first, under a workspace key we never receive. That is not a policy. It is that we cannot decrypt it, for you or for anyone. Some coordination metadata is still in the clear, and here is exactly which.

● Encrypted on your machine

  • File contents
  • File paths
  • Diffs
  • Content hashes
  • Change intents, the descriptions attached to a change

A database dump or a subpoena gets ciphertext.

○ Visible to the service

  • Your account email and the workspace, device, and project identifiers
  • Your repository's Git remote URL
  • Timestamps, file counts, and payload sizes
  • Whether a file was added, modified, deleted, or renamed, but not which file
  • Task titles, claim targets, published intents, handoff notes, and validation output, which are not encrypted yet

If any of those are confidential for you, self-host the service.

No third-party model provider is in the loop either. The AI reviewer for ambiguous conflicts runs on the coding agent already connected to your machine. Read the privacy page for the full list and what happens if you lose your key.

Install

One command, in the repository your team shares

It configures the checkout, signs you in, attaches you to a workspace, starts the daemon, and registers the Crosscode MCP server with your coding agent. Re-running it is safe: every step it has already done is skipped.

run in your project 
npx crosscode-cli start

Using it daily? Install it properly so the daemon runs from a stable path instead of npm's cache: npm install -g crosscode-cli, then crosscode start. To bring a teammate in, generate an invite and have them run crosscode join --invite <code> in their own checkout.

Or hand the whole thing to your agent

Paste this into Claude Code, Codex CLI, OpenCode, Cursor, or any other MCP-capable agent. It runs the same command and wires up the MCP config itself.

paste into your coding agent 
Set up Crosscode for this project. Crosscode keeps everyone working on this
codebase in sync: a local daemon watches Git and filesystem activity and exposes
itself to you (my coding agent) as an MCP server, so you can see what my teammates
and their agents are doing in their own checkouts, and they can see what we do here,
within seconds instead of at pull-request time. Their work arrives as proposals we
review, never as writes into our files. Do the following:

1. Check that Node 24 or newer is available (`node --version`). If it is not, stop
   and tell me, because everything below needs it.
2. From this project's Git root, run:

   ```
   npx --yes crosscode-cli start --no-browser
   ```

   `start` does the whole setup: it configures this checkout, signs me in, attaches
   it to my personal workspace, starts the background daemon, and writes the
   Crosscode MCP server into this project's MCP config. It registers with Claude
   Code (`.mcp.json`) by default; pass `--mcp cursor`, `--mcp gemini`, or
   `--mcp opencode` if I use one of those instead.
3. `--no-browser` makes it print a sign-in URL instead of trying to open a browser
   you cannot see. Show me that URL and wait. I have to open it and sign in, or
   create an account, before the command finishes. Do not try to sign in for me,
   and do not ask me for my password.
4. If I say I would rather not use a browser at all, run it headlessly instead:
   `npx --yes crosscode-cli start --email <my email> --password <my password>`,
   using credentials I give you. If I have no account yet, that path needs
   `npx --yes crosscode-cli signup --email <e> --password <p>` first.
5. Once `start` reports success, tell me the config was written and that I need to
   restart/reload you (or reconnect MCP servers) for the new "crosscode" server to
   be picked up.
6. Once reconnected, call the `get_workspace_state` tool once to confirm it works.
   If the call fails, report the exact error back to me instead of guessing at a
   fix.

If I am joining a teammate's workspace rather than using my own, run
`npx --yes crosscode-cli join --invite <code>` with the invite code I give you
after step 5, then restart as above.

Codex CLI's config is TOML and start does not write it, so Codex users add a three-line entry by hand. See MCP client setup.

Pre-1.0

What works, and what does not

The loop works end to end: capture, sync, review, accept, publish. Some of the hosting around it is still being finished.

Working

  • A per-checkout daemon that captures every settled edit durably, and survives restarts
  • An MCP server that starts that daemon on the first tool call
  • Workspaces, members, roles, invite codes, and one-time pairing codes, all self-serve
  • Live presence, tasks, claims, handoffs, and intents
  • End-to-end encrypted file payloads, on by default
  • Binary files restored byte for byte, and renames tracked as renames
  • publish --branch, with a dry-run plan first
  • An advisory AI reviewer that runs on your own agent, off unless workspace policy turns it on

Not yet

  • Live push through the hosted service is polling rather than a held-open socket, so remote work appears on the next sync. Self-hosting gets you the WebSocket path.
  • No live Stripe account exists yet, so no real card has moved a workspace between plans. Plan limits are enforced server-side regardless.
  • Task titles, claim targets, intents, and validation output are not encrypted yet. File payloads are.
  • Dependency-impact analysis for TypeScript is a syntactic walk, not a type-checker-backed one.
  • There is no web app and there will not be one. Workspaces, invites, and billing are CLI and API only.

Questions

Asked before installing

What do I actually have to set up?

Node 24 and a Git checkout. Run npx crosscode-cli start in the repository your team shares and it does the rest, including giving your account a workspace. Teammates run the same command and join with an invite code. Teams who would rather hold their own data can run the coordination service themselves, from one Node process or the included Dockerfile, backed by a Supabase project. The install guide covers that.

Can you read my code?

No. File contents, paths, diffs, content hashes, and change intents are encrypted on your machine before they are sent, with a key we never receive. What we can see is your account email, your Git remote URL, timestamps and sizes, and for now task titles, claim targets, published intents, handoff notes, and validation output, which are not encrypted yet. The privacy page lists all of it.

What happens if I lose the encryption key?

You lose the coordination history, meaning past proposals and their diffs. You lose no source code, because your repository is an ordinary Git repository on your disk the whole time. We cannot recover it for you, which is the same fact as not being able to read your code. Print a recovery code with crosscode key export and keep it in your password manager. Any other paired machine can also hand the key to a new one.

Can it rewrite my branch history or force-push?

No. Crosscode never stages, commits, pushes, resets, rebases, or changes remotes on its own, and it never moves HEAD. Checkpoints live under refs/crosscode/checkpoints/, outside branch history. The safety model has the exact rules.

What happens if I stop running it?

Your repository is an ordinary Git repository the whole time, so nothing about your checkout changes. There is no lock-in format to migrate away from.

Which coding agents work with it?

Any MCP-capable agent. Claude Code, Codex CLI, OpenCode, Cursor, Gemini CLI, and VS Code are in use today. It is a standard stdio MCP server, so anything that can add one can use it. There is no editor extension, by decision: MCP is the single integration contract.

Does my code get sent to an AI provider?

No. The AI reviewer for ambiguous conflicts runs on the coding agent already connected to your machine, so nothing leaves it and there is no third-party model provider involved. That is also why AI review is unlimited on every plan including free: it costs us nothing.

What does it cost?

Free for up to five people or agents, forever. Paid plans start at $2.50 a month, or $25 a year for the same plan. Self-hosting is free with no limits. See pricing. No live payment account exists yet, so nothing is chargeable today.
