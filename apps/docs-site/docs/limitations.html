Current limitations

What is not built yet, and what is built but rough. Crosscode is pre-1.0 and this page is deliberately blunt.

Not shipped yet

  • GitHub OAuth sign-in is still landing, which means crosscode start cannot yet complete the sign-in step end to end on a clean machine.
  • The Claude Code and Codex pre-edit hooks are written but not verified firing before every file edit. Until they are, an agent finds out about a conflict on its next tool call rather than before it writes.
  • The full quickstart has not been verified on a fresh machine, so treat the under-60-seconds claim as a target rather than a measurement.

Privacy and hosting

  • There is no end-to-end encryption. Files are encrypted in transit and at rest under keys the service manages, so someone with production access could read the files you sync. The privacy page lists exactly what is stored. E2E was built once and removed: it cost a device-pairing ceremony, a keyring, rotation, and recovery paths, for a product whose durable artifact is a Git repository you already have.
  • Hosted only. There is no supported self-hosted deployment of the coordination service. The software is MIT licensed, so you may run your own, but it is not a supported configuration.
  • Billing does not exist. The hosted service is free, no payment provider is wired up, and nothing is chargeable.
  • Workspaces, invites, and projects are CLI and API only. There is no web app for syncing and there will not be one. This site is a landing page, sign-in, and docs.
  • Deliberately no editor extension. MCP is the only integration contract, so editors connect the same way agents do.

Performance and robustness

  • Watcher performance on a large monorepo has not been measured. A file watcher over a very large tree is not free, and this is a known risk rather than a solved problem.
  • Battery and CPU cost over a real workday have not been measured.
  • Three-way convergence is proven for two replicas. More than two has not been exercised end to end.
  • Under sustained typing, a hot file can defer indefinitely: the ten-second rule has no ceiling on it yet.
  • Large files and binaries are handled but not tuned. Binaries are never merged, so concurrent binary edits are always a conflict.
  • The retention job and resync behaviour under bad networks still need hardening.

Known risks

  • Writing to a file that has an unsaved editor buffer, or one an agent is part-way through editing, is the sharpest edge in the product.
  • Syncing a secret would be a serious incident, which is why untracked files are never sent and the denylist drops credential-shaped paths before capture rather than filtering later.
Do not treat anything absent from what works today as available. The repository's PLAN.md is the single source of truth for what is done.
