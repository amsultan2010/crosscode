Current limitations

Taken directly from this repository's README.md.

  • Production PostgreSQL role grants and retention policies still need environment-specific deployment hardening.
  • Supabase session refresh tokens are stored in the OS keychain when available (macOS Keychain, Linux Secret Service); otherwise, including on Windows, the protected Git-directory configuration file is used.
  • Binary files are shared base64-encoded with byte-exact materialization; any conflict involving a binary file requires human approval, since deterministic hunk/merge analysis is text-only.
  • Renames are tracked as first-class rename changes; a rename conflicting with pending work on either path, or touching a critical path under either name, always requires approval.
  • Dependency-impact analysis for .ts/.tsx is a syntactic AST walk, not a type-checker-backed analysis.
  • There is no hosted or managed coordination service yet. You run a Supabase project (or a plain Postgres instance for local-only testing) and the service yourself.
  • Workspace and member provisioning is still an administrator-side command (service:provision); there is no self-serve signup or billing yet.
  • Deliberately not published to npm or any editor marketplace — the supported surface is the daemon + MCP server, run from a cloned checkout. Editors like VS Code and Cursor connect via MCP; there is no supported editor extension.
This is a functionality-first, pre-1.0 project. Do not treat anything on this page, or absent from the what works today list, as available.
