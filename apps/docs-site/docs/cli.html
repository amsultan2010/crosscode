CLI reference

The crosscode CLI is minimal and scriptable. Every command supports a stable --json output mode for agents and scripts; default human output is concise. From a checkout, invoke it with pnpm crosscode -- <command>.

This page lists the CLI command surface as specified in BUILD_INSTRUCTIONS.md section 15. See current limitations for what is and isn't finished, and the install & quickstart guide for commands in context.
CommandPurpose
crosscode initInitialize local Crosscode state for this checkout.
crosscode -- login --email <email> --password <password>Sign in against Supabase Auth and store the session (access token in memory, refresh token in the OS keychain when available). Self-registers this replica automatically on first daemon start.
crosscode -- logoutClear the stored Supabase session for this checkout.
crosscode join --workspace <workspaceId>Explicitly select a workspace for an already-logged-in session.
crosscode status --jsonShow repository, daemon, outbox, cursor, and service health.
crosscode task create "Implement checkout API" --path server/routes/checkoutDeclare a task and the paths it covers.
crosscode claim path src/checkout --task <id>Advertise an advisory claim on a path for a task.
crosscode intent "Add paymentStatus to CheckoutResponse" --task <id>Publish a plain-language intent for a task.
crosscode proposals listList remote operations proposed to this replica.
crosscode accept <operation-id>Materialize an accepted proposal after re-checking the local base and creating a checkpoint.
crosscode reject <operation-id> --reason "..."Reject a proposal; no local files are changed.
crosscode checkpoint [--message "..."]Create a hidden Git checkpoint without moving HEAD or the index.
crosscode validate [--profile affected]Run commands from a committed .crosscode/config.yaml validation profile.
crosscode publish --branch <branch>Create ordinary commits on a branch from accepted, validated state. Requires confirmation unless run noninteractively with an explicit --yes flag and workspace policy allows it. Never force-pushes.
crosscode run -- <tool-and-arguments>Run an arbitrary local tool/command under the current checkout.

JSON output

Every command accepts a --json flag. Scripts and agents should always pass it; default (non-JSON) output is intended for humans reading a terminal and is not a stable interface.
